# Phase 2 独立验收节点 — 全部由用户操作

本轮 **没有执行** 构建、自动测试、烧录、扫描连接、刺激输出、手机实测或示波器测试。下面每项均需用户记录结果；任何失败都先停止刺激并保留原始日志，不向后宣称通过。

## 当前原型配置

2026-11-02 用户已确认沿用旧 RX 接法：ISET P0.18、#VNS_EN P0.16 低有效。无需 BOARD_CONFIRMED 或 EXPERIMENT_APPROVED 开关。默认 UI 为 1 mA / 15 Hz / 250 µs / 30 s，30 s 来自旧固件默认；软件范围来源和单位见 README.md / rx_profile.h。

用户进一步确认沿用旧 RX 硬件，无电压检测部分。新增的 ADC/电压门槛已移除，App 不显示 VDD/VRECT，也不据此阻止 Apply/START。协议中的电压槽保留为零（未测量），供电检测 flag 不伪装置位；本版本没有主动欠压检测。

沿用旧 ISET 模型；假负载检查电流和脉冲仍用于判断真实输出是否符合设定，不是新增批准流程。所有下列操作均由用户执行。

## A. RX 单独上电、复位与禁止状态

- 先实体禁止输出，只接假负载/测量设备，绝不接人或动物。
- 用示波器监测实际使能节点：上电、电源慢升、MCU reset、烧录、看门狗 reset、蓝牙连接前都应禁止；确认没有窄毛刺。
- 确认 ISET 默认不产生有效输出参考，P0.16 在上电/复位时保持禁止。物理默认电平由板上电路保证。
- 用外部仪器检查电源；软件不读取或显示电压，不再等待 3.0 V / 200 ms 判据。
- 独立通过条件：真实极性/默认电阻确认、复位期间不意外开启。当前状态：**未验证**。

## B. 假负载恒流与本地硬件脉冲

- 先完成 A 的默认电平检查和 C/D 的通信检查，再手动 Apply/START 观察假负载。当前直连版本不做身份认证，不提供上电自动输出自检模式。
- 按真实顺应电压、压降余量和功率选择假负载及取样电阻；不在未知电路上照抄负载电阻值。测量 `I = V_sense / R_sense`。
- 首先检查界面显示的默认工作点 1 mA、15 Hz、250 µs、30 s；按实际负载测试需要修改。不得把这些工程默认当作人体或动物使用建议。
- 示波器同时看 ISET PWM、独立使能和负载电流。核对约 100 kHz PWM、15 Hz 对应约 66.667 ms 周期、设定脉宽、RC 建立时间及持续时间。
- 同时看 P0.12 LED2：每个 LED 包络必须与刺激使能脉冲同步；载波约 100 kHz，占空比应与同一次 ISET 量化设置一致。LED 亮度不是实际电流测量值。
- 改变两个电流设定，比较 P0.12 的 PWM 占空比；随后分别执行 STOP、断开 BLE、等待通信超时和持续时间结束，确认 LED2 均保持低电平。
- 区分请求电流、PWM 量化设定值和真实测量值；1 mA 在旧模型下向下量化约 994 µA，不是仪表测量结果。容差由硬件/实验要求确定，不虚构合格容差。
- 在 BLE 流量变化时验证脉冲边沿仍来自 TIMER/PPI/GPIOTE；不应出现随包间隔变化的脉宽。检查电荷平衡/耦合结构，软件单使能不等于双相输出。
- 独立通过条件：假负载下恒流/脉冲/默认关闭/截止行为达到批准要求。当前：**未验证**。

## C. Wireless Power 自动连接与重连（当前无配对码版本）

- 用户自行构建并烧录当前 TX/RX，更新 WebApp；不运行 provisioning 脚本，不需要 PIN 或首次认证。
- 手机 Connect TX → Control → Power ON，应主动扫描 `VNS_RX_01` + RX Service，发现 GATT 后自动回传状态。
- 广播名称在扫描响应中，检查主动扫描能取得它；错误名称或错误 Service 不应连接。
- RX 断电再上电且 TX Power 保持 ON，应自动重连；Power OFF 应停止连接与重试，再次 ON 应立即开始搜索。
- 同名同 UUID 并不能证明同一设备；本原型不承诺拒绝仿冒或保存 bond，后续身份绑定另行设计。
- RX 断线不得误停手机 ECG/PPG。重连必须输出 OFF/LOCKED，新 nonce、清除 configured、不恢复 START。
- RX 只有一个 BLE 连接；其他工具直连 RX 时，先断开该工具再测试 TX 自动连接。
- 当前：**未构建/未实测**。

## D. 参数、ACK 和错误

- 先 QUERY，核对 RX nonce、limits 和实际状态。
- 在输出驱动初始化和有效参数就绪后，CONFIG/START 应能收到真实 RX ACK；不得用 TX 本地应答冒充。
- Apply Parameters 成功应同时收到匹配事务的 `RX_STATUS OK` 和 `RX_PARAMS`。随后 START；只看到 TX 本地接收或 ATT write success 不能算通过。
- 发送越界值、过长脉宽、错误 nonce、旧事务、重复 START；必须拒绝并关闭输出，不得重放命令或延长原持续时间。
- STOP 打断 pending 命令/settling；测试过期 START 已进入队列时 STOP 仍阻止后续定时器启用。
- 当前：**未验证**。

## E. 手机–TX–RX 完整链路

- 手机通过原 TX 连接，再用独立 Stimulation 页面；主监测 Service、CSV 内容和采样时间不变。
- 检查 TX/RX 状态、Wireless Power、参数单位、实际设定值、ACK 来源、剩余时间及故障；所有 GUI 文本应为英文。
- 缺 RX、状态过期、link 不就绪、输出初始化失败或参数非法时 START 必须禁用。修改草稿后重新 Apply，不隐式更新正在运行的输出。
- 隐藏页面、关闭页面、断开手机都应停止租约；回到页面/重连不能恢复刺激。
- 当前：**未验证**。

## F. 双 BLE 与 Phase 1 回归

由用户在 WebApp 目录执行：

```sh
pnpm test
pnpm build
```

包括新 `gatewayProtocol.test.ts` 和原有传感器解析、滤波、HRV/SpO2 与 CSV 测试；本轮未运行。

- 先在 RX 未 START/供电 OFF 下复核 ECG/PPG/温度采集、IR 0.5–3 Hz 默认、ECG 红实线、HR/HRV、原始及滤波 CSV。
- 再打开匹配名称/Service 的 RX、双 BLE、Wireless Power，假负载刺激并持续采集。检查 ECG 256 SPS、PPG 100 SPS 的 index/time 连续性、FIFO overflow、丢样/发送失败计数。
- 验证 PPG 故障仍不阻塞 ECG/温度，RX 断线不覆盖手机 peer，不产生重复通知订阅。
- 使用实际协商 MTU 23 与较大 MTU 分别检查，确认协议不截断；关注手机连接调度、第二条连接和扫描的吞吐影响。
- 检查 map、RAM、stack watermark；双连接增量未构建前不能声称 64 KiB 足够。当前不进行 SMP 配对或 bond 写入。
- 当前：**未验证**。

## G. 故障注入

- 在假负载上改变线圈耦合，用外部仪器观察 VRECT、LDO VDD 和电流；用户根据仪器结果 STOP。当前 RX 不做主动电压检测，不能将模拟供电不足但 MCU 仍运行时的主动欠压关断记为已实现。
- 断开 RX BLE、手机 BLE、关闭 Wireless Power、取消 CCC、关闭页面、阻塞通信超过 1.5 s；示波器量化最后一个输出边沿和关断延迟。
- RX TIMER4 租约截止和 TIMER3 session 截止应直接禁止未来 ON 路由并拉到 OFF，不依赖新的 BLE STOP 包；特别检查截止与脉冲边沿接近时的竞态/毛刺。
- reset/看门狗/参数错误均应禁止；供电下降导致实际 MCU reset 时需检查物理使能恢复 OFF，当前没有独立软件欠压判断。关断后恢复供电/重连只能回到 OFF，需要新的 CONFIG、START。
- 不把无线供电 XKT enable 状态当成实测 RX 供电或输出电流。
- 当前：**未验证**。
